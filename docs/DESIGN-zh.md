# 北京 H-1B 空位监测与预约助手：Muse 设计与交接文档

## 1. 目标与当前事实

基于 https://github.com/yalewinters/visa-slot-watcher 改进，保留原项目的产品方向：扩展界面、状态记录、空位监测、桌面／手机通知、定时检查和明确开启的预约模式。

用户最终希望自动预约；随后明确确认：**目前没有获准的实时接口，先完成模拟自动预约。** 未授权的保护网站访问、人机验证规避和真实自动预约不属于已实现功能。

| 配置 | 值 |
|---|---|
| 登录入口 | https://www.usvisascheduling.com/en-US/ |
| 预约入口 | 登录后通过站内导航进入，不假设深层链接能启动 |
| 地点 | Beijing；用户账号目前仅一个领馆 |
| 签证类别 | H-1B |
| 日期区间 | 2026-12-07 至 2027-01-08，包含两端 |
| 业务时区 | Asia/Shanghai |
| 期望频率 | 每 30 分钟，持续运行时名义每天 48 次 |
| 手机通知 | ntfy 或 Telegram |

当前仓库根目录是独立 Node.js 模拟工具，不是原 Chrome 扩展的全功能版本。后续扩展开发应参考保存的原版恢复界面，复用已测试的业务逻辑。不要把模拟结果当作官网真实空位。

## 4. 推荐架构

```text
扩展 UI（弹窗、设置、状态、操作记录）
                  │
监控协调器（模式门控、登录状态、调度、并发与恢复）
                  │
Provider → 标准化快照 → 日期／状态引擎
                           ├─ 通知模块
                           └─ 预约模块
```

模块边界：

1. `MockProvider`：离线 fixture 与确定性演示，不访问官网。
2. `AuthorizedProvider`：获准 API 或数据服务；权限范围及频率需核验。
3. 用户主动页面读取适配器：仅在确认网站规则允许且用户明确启动后开发。手动登录不自动构成定时访问或预约提交许可。
4. 日期／状态引擎：纯函数，不依赖浏览器或网络。
5. 通知模块：最少数据、固定目的域、超时和安全错误码。
6. 预约模块：与查询授权独立；模拟和真实实现严格分离。

现有 `authorized-file` 只读取本机规范化文件，不会从官网取得数据。配置中的授权记录是用户声明，不能自行产生或证明服务商许可。

## 5. 登录、首页与人工验证

用户报告直接打开 `/schedule/` 可能 timeout；先打开 `/en-US/` 登录，再点击站内预约入口可以工作。应将此作为导航要求和待验证观察，不把所有 timeout 都归因于深层链接。

目标流程：

```text
首页 → 必要的人机验证 → 用户登录 → 站内预约入口 → 身份／范围核验 → 日历
```

状态至少包括：`SIGNED_OUT`、`HUMAN_ACTION_REQUIRED`、`READY`、`QUEUED`、`RATE_LIMITED`、`ACCESS_RESTRICTED`、`ERROR`。

发现 Verify human／CAPTCHA 时停止自动交互，提示用户亲自完成；不得自动点击验证控件、使用代解、伪造身份、切换出口或刷新规避限制。完成后重新读取页面状态，再决定恢复。若每次都需要验证，明确告知无法无人值守。

密码、验证码和安全问题答案只由用户在官网或系统密码管理器输入，不在聊天、扩展存储、JSON、日志或源码中收集。不导出 cookies、session token 或浏览器配置。会话失效后暂停，不进行无限登录尝试。

## 6. 北京与 H-1B 身份核验

单领馆账号可以省去重复选择，但不能省去身份核验。只有明确属于 Beijing 和 H-1B 的数据可以提醒或作为预约候选。

如接口使用领馆 ID、签证类别代码或本地化名称，建立明确映射并用获准样本验证。不得假设第一项就是北京。无法证明时返回 `SCOPE_UNVERIFIED`。

## 7. 标准化快照目标格式

以下为下一版建议契约，**现有模拟版尚未采用全部字段，需要版本迁移**：

```json
{
  "schemaVersion": 2,
  "providerId": "mock",
  "status": "ok",
  "location": "Beijing",
  "visaType": "H-1B",
  "observedAt": "2026-11-13T10:00:00+08:00",
  "coverage": {
    "start": "2026-12-07",
    "end": "2027-01-08",
    "complete": true
  },
  "appointments": [
    {"date": "2026-12-07", "status": "confirmed_available", "slots": []}
  ]
}
```

`confirmed_available` 表示已验证的 provider 明确声明可用，不表示已保留名额。`inferred`、`unknown` 不得触发新提醒或预约。`unavailable` 表示明确不可用。解析和 provider 错误单独处理。

严格校验真实日历日期；日期值按北京当地日期解释，带时区时间戳转为北京日期。拒绝无时区时间戳。HTTP 200 不等于业务成功；登录 HTML、维护页、错误 JSON 和 schema 改变都不能解释为无空位。

只有完整覆盖目标范围的有效快照才能通过缺席判定消失。单个月份响应必须标为部分覆盖，或先由适配器合成两个月的完整快照。不得把启发式找到的日期直接标为 confirmed。

## 8. 去重与重新出现

按日期及必要的 provider／范围身份追踪出现轮次：

```text
未知 → 确认可用 → 已通知 → 确认消失 → 再次确认可用 → 再次通知
```

持续可用不重复提醒。完整有效快照缺席或明确 unavailable 才清除当前出现状态。timeout、部分快照、推测和解析失败保留前次状态。发送失败不能标为已送达，后续重试前需重新确认仍然可用。

状态跨进程重启、浏览器重启和扩展后台休眠持久化。推送和本地落盘无法原子提交，需记录可能出现的崩溃后重复提醒限制，不能宣称 exactly-once。

## 9. 调度与失败恢复

自动检查默认关闭；显式启用且 provider 许可覆盖该频率后才能运行。每 30 分钟一次，同任务最多一个检查，持久化最近尝试，失败也消耗该次频率窗口。休眠后不密集补发。

每次检查重新核验许可有效期和目标结束日期。若 provider 限频更严格，采用更低频率或拒绝不符合约束的配置。48 次只是持续可运行时名义频率，休眠、网络和限制可能减少次数。

- 会话失效：暂停，提示登录。
- 人机验证：暂停，等待人工。
- 429：遵守 Retry-After，不立即重试。
- 明确访问限制：停止并报告。
- 网络故障：保留状态，按许可的退避策略恢复。
- schema 变化：暂停适配器，不猜测为空。
- 通知失败：固定错误码；重新确认空位后再重试。

## 10. 手机通知与本机桥接

ntfy：用户安装 App、订阅随机主题，按服务支持情况限制访问，发布 token 使用系统秘密存储。Telegram：用户创建 bot、先发起聊天，bot token 使用系统秘密存储。

Chrome 扩展不能直接读取 macOS 钥匙串。若选择扩展加本机秘密存储，应开发受限 Native Messaging Host：

- 只允许明确的扩展 ID。
- 只接受固定消息类型和经过校验的日期。
- 不接受任意 URL、命令、shell 参数。
- 本机进程读取钥匙串并发送推送。
- 安装与卸载流程完整展示组件和权限。

现有独立 Node 工具支持钥匙串读取和通知发送，但**不是已经集成的 Native Messaging Host**。

消息只含北京、H-1B、日期、检查时间、时区、官网链接及模拟／真实标识。不含账号、申请编号、密码、答案、cookie 或原始响应。提供独立测试按钮，测试消息显著标注 TEST ONLY。手机送达需在用户设备实测。

## 11. 预约模式

三种产品模式：只提醒、模拟自动预约、真实自动预约。当前仅前两种可开发／运行，真实模式明确标为不可用。

模拟模式需显式开启，只选确认可用且符合范围的最早日期；每次任务最多一条模拟记录，重启和重复数据不重复预约。结果为 `SIMULATED_ONLY_NO_REAL_APPOINTMENT`。仅有日期而无时间段时，称为日期选择模拟，不能宣称完成预约。

真实模式上线前必须满足：独立的预约操作许可、明确申请人及范围、真实 slot／容量标识、用户开启、费用及重约影响确认、重复提交保护、提交前重新校验、提交后可靠结果核验。

提交 timeout 必须进入 `BOOKING_RESULT_UNKNOWN`，先核查是否已成功，不自动重提。没有这些条件时，不得通过隐藏开关恢复原版提交脚本。

## 12. UI、日志与数据保护

UI 展示：当前模式、provider 状态、登录／验证状态、北京 H-1B 范围、最近尝试和最近成功时间、数据新鲜度、覆盖范围、下一次允许检查、推送状态和预约结果。提供暂停／恢复／手动检查。

日志采用允许列表：固定事件类型、状态码、时间和允许显示的日期。禁止原始请求响应、敏感 URL 参数、token、cookie、密码、答案及未清理底层异常。

升级时提示清除旧扩展凭据并卸载旧版本；新代码不能保证擦除浏览器备份中的历史明文秘密。不要把旧凭据迁移进新实现。

## 13. 测试与验收

必须覆盖：

- 12/06 排除、12/07 包含、01/08 包含、01/09 排除。
- 12/31 到 01/01 的跨年和 UTC 16:00 北京日期变化。
- 不同主机时区结果一致。
- 可用、推测、不可用、未知、失败及格式错误。
- 北京／H-1B 身份不明或错误时不提醒／预约。
- 部分／单月响应不清除未覆盖月份状态。
- 首次提醒、持续可用不重复、消失重现再次提醒。
- 故障不制造消失事件；重启保留去重状态。
- 并发锁、最小频率、休眠恢复和授权过期。
- 推送失败、测试标记、日志无秘密。
- 模拟预约最早日期、明确开启、仅一次及重启不重复。
- 真实预约未来测试必须覆盖结果未知时不重提。
- 首页导航、登录失效和人机验证暂停。

所有离线测试不得访问签证网站。真实联调另记许可范围、环境、步骤、观察与未验证部分。离线测试通过不等于真实功能可用。

8. 独立评估真实预约条件，未满足前保持不可用。
